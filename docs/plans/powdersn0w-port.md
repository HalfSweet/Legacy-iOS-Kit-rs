# Porting powdersn0w (xpwn-based custom IPSW builder) — implementation plan

Source baseline: [LukeZGD/powdersn0w_pub](https://github.com/LukeZGD/powdersn0w_pub) `main` (`xpwn/ipsw-patch/main.c` etc.); driver behavior from upstream `restore.sh` @ `1ff4be0`.

## 1. Invocation matrix

Legacy-iOS-Kit shells out to a single `powdersn0w` binary built from `xpwn/ipsw-patch/main.c` (the sibling `daibutsu.c` is a separate standalone binary and is **never invoked** — see §2). Three call sites:

**A. `ipsw_prepare_32bit` (restore.sh:4145)** — single IPSW, no `-base`:
```
powdersn0w in.ipsw temp.ipsw [-daibutsu] [-memory] -ramdiskgrow 10 [-bbupdate] [-punchd] \
    [systemversion.tar] [iBoot.tar] [baseband-$ecid.tar] [activation-$ecid.tar] <JB tars...>
```
Reached for: A4 (`device_proc==4`) targets that are latest-version+jailbreak, `--other`, gasgauge, tethered-beta etc.; A5/A6 (`device_proc` 5/6) non-latest-version or gasgauge restores; and as part 2 of `ipsw_prepare_ios4multipart` (3.x/4.0–4.2.x, with `$1=iboot` for iPad1,1). Redirects: ≤4.1 → `ipsw_prepare_jailbreak` (not powder), 10.x → return. Non-jailbreak builds are skipped unless `ipsw_nskip`, build `9A406`, A4, actrec, tethered, or beta.

**B. `ipsw_prepare_powder` (restore.sh:5701)** — A5/A5X/A6 two-bundle mode: adds `-base base.ipsw`; bundles generated for both `target` and `base`; iBoot pre-patched externally via `patch_iboot` (existing `image::iboot32`) and passed as `iBoot.tar` for iPhone5,\* (ramdiskH, `--boot-partition[9] --boot-ramdisk [-b bootargs]`) and iPad1,1 (iBoot renamed to iBEC).

**C. `ipsw_prepare_ios4powder` (restore.sh:5604)** — 4.3.x single-IPSW powder: `-base` **plus the only use of `-apticket <shsh>`**; `src/bin.tar` replaced by `bin4.tar`; config forced to `false true`.

Jailbreak payload matrix (`$jelbrek = resources/jailbreak`):

Common extras: `-memory` (in-memory buffer) when `ipsw_memory`; `-bbupdate` when device has baseband and isn't `device_disable_bbupdate`; `systemversion.tar` for betas (generated plist tar); `baseband-$ecid.tar` when bbupdate disabled but baseband live; `activation-$ecid.tar` when actrec. openssh option appends `sshdeb.tar`, `openssh.tar`, `openssl.tar` (gunzipped). `LukeZGD.tar` is omitted for 3.x/4.x in path A but always added in path B. In path B, `freeze.tar` is omitted for 6/8/9 targets (bootstrap then comes from the generated bundle's `FilesystemPackage`).

`config.plist` (generated by `ipsw_prepare_config`, restore.sh:3815): `FilesystemJailbreak=true` **only for jailbroken 6.x/8.x/9.x targets**; `needPref=true` for target bundles; `iBootPatches.bootArgsInjection` + string when verbose (`pio-error=0 -v`) or custom `--bootargs`.

`ipsw_prepare_bundle` (restore.sh:3874) generates a runtime bundle `FirmwareBundles/[BASE_]<device>_<vers>_<build>.bundle/Info.plist` containing: `Filename`, `RootFilesystem`, `RootFilesystemKey`, `RootFilesystemSize` (from ramdisk `options*.plist` `SystemPartitionSize` + 30), `RamdiskOptionsPath`, `SHA1` (whole-IPSW SHA-1), `Firmware` dict (iBSS [+iBEC] with `Patch=true`, RestoreDeviceTree, RestoreKernelCache with `DecryptPath=Downgrade/...` for 5/7 **or** KernelCache with `Patch=true` for 6/8/9, RestoreRamdisk; all with `Decrypt=true`), `FirmwarePath`/`FirmwareReplace` (NOR image paths for `-base` mode), `FilesystemPackage`/`RamdiskPackage` (`bootstrap=freeze.tar`, `package=src/ios9.tar` for 8/9, `package=src/bin.tar`, `ios=ios<N>` marker), and for daibutsu: `RamdiskPackage2=./bin.tar`, `RamdiskReboot=./reboot.sh`, `UntetherPath=./untether.tar`, `hwmodel`. For `-base` mode it also emits `RamdiskExploit={exploit=src/target/<hw>/<base_build>/exploit, inject=partition}`.

**FirmwareBundles shipped in upstream Legacy-iOS-Kit**: 54 `Down_*.bundle` directories under `resources/firmware/FirmwareBundles/` (iPhone1,1×1, iPhone1,2×3, iPhone2,1×26, iPhone3,1×4, iPod1,1×1, iPod2,1×7, iPod3,1×7, iPod4,1×2, iPad1,1×3). They contain **only `.patch` bsdiff files** (asr/restoredexternal/lockdownd/iBSS/iBEC/iBoot/LLB/kernelcache/WTF) — no `Info.plist`. They serve the classic `ipsw` tool path, **not powdersn0w** (powder mode explicitly ignores them: `FirmwareBundle2=` when `ipsw_prepare_usepowder=1`). Out of scope for this port.

## 2. Code path map (main.c, 1538 lines, fully read)

Execution order in `main()`:
1. Arg parse: `-memory -daibutsu -punchd -s -S -ramdiskgrow -bbupdate -base -apticket`, then payload tar list.
2. `parseIPSW2`/`parseIPSW3` (pwnutil.c): SHA-1 the whole IPSW, match against `Info.plist` `SHA1` in bundle dir, `loadZip2/3` (minizip via outputstate.c). **In Rust this collapses to direct typed bundle construction — no hashing/matching needed.**
3. Read `config.plist` → `jailbreak`, `needPref`, boot-args assembly (`CSBYPASS_BOOTARGS` + extras; `jailbreak` implies `debugMode`).
4. **`-base` block** (`FirmwareReplace` loop): `APTicket` → reseal DER ticket into `scab_template` IMG3 (needs `-apticket`; marked "buggy" upstream); `manifest` → copy bundle `manifest` file into `all_flash/manifest`; path capture. Then `FirmwarePath` loop: copy base-IPSW NOR images (AppleLogo, BatteryCharging0/1, BatteryFull, BatteryLow0/1, BatteryPlugin, RecoveryMode, LLB) over target paths; rewrite IMG3 TYPE tag byte `+0x10`/`+0x20` `logo→logb`, `recm→recb`, `ibot→ibob`; `NewiBoot` → `doiBootPatch` (iboot.c) with boot-args + `PATCH_DEBUG` when jailbreak, then `doDecrypt` (patched iBoot2 stored decrypted); original base iBoot → `ibot` path.
5. **`Firmware` dict loop**: `iBSS`/`iBEC` with `Patch=true` → `doiBootPatch` (always `PATCH_DEBUG`, boot-args = `CSBYPASS_BOOTARGS` + extras). `KernelCache`: `DecryptPath` → decrypt copy to `Downgrade/RestoreKernelCache` + rewrite BuildManifest paths + optional `doKernelPatch` on the copy; if `jailbreak` → `doKernelPatch` on stock kernelcache (kernel.c `patchKernel`); `Decrypt` → raw decrypt. Other entries (`RestoreDeviceTree`, `Restore Ramdisk`, …): `Decrypt`/`DecryptPath` + manifest path rewrite. Manifest rewritten into output if dirty.
6. **RootFS**: FileVault-decrypt (`RootFilesystemKey`) + `extractDmg`; `grow_hfs` to `RootFilesystemSize` + per-tar MB estimate (+untether/bootstrap/package sizes); `-punchd` → move `/sbin/launchd`→`/sbin/punchd`; untar every payload tar; daibutsu moves (`CrashHousekeeping`, Cydia.Startup plist, `/Library/LaunchDaemons`→`/tmp/.LaunchDaemons`, then after untether: move `/System/Library/LaunchDaemons`+`NanoLaunchDaemons` to `/Library/`, recreate dir, relocate bootps/CrashHousekeeping/MobileFileIntegrity/mDNSResponder/softwareupdated plists, jetsamproperties per `hwmodel`, chmod CrashHousekeeping); untether tar; `jailbreak` → remove+write hardcoded rw fstab (`fstab.h`, 63 bytes, runs **after** tar merge so it wins), untar `bootstrap` (freeze.tar) and `package` (ios9.tar); `needPref` → write `com.apple.springboard.plist` pref blob (`pref.h`, 76 bytes, 0600 mobile:mobile).
7. **Ramdisk**: open (KBAG key/IV if present, else plain), grow by `ramdiskgrow` + payload-derived blocks (usage string says *blocks*; verify — see §5), `doPatchASR` on `usr/sbin/asr` (asr.c), untar `RamdiskPackage` (bin.tar), `-base` → move `/sbin/reboot`→`/sbin/reboot_`, install `partition` script as `/sbin/reboot`, install `exploit` as `/exploit`, chmod/chown; dummy `ios<N>` marker file; `createRestoreOptions` (pwnutil.c): rewrite `options*.plist` → `CreateFilesystemPartitions=true`, `SystemPartitionSize=<grown root MB>`, `UpdateBaseband=<bbupdate>`, `MinimumSystemPartition` removed/readded; daibutsu → `/sbin/reboot` hook = `reboot.sh`, untar `RamdiskPackage2` (daibutsu bin.tar) into ramdisk.
8. Remove `Update Ramdisk` entry (never emitted by Legacy-iOS-Kit bundles), `buildDmg` rootfs back to UDIF, `writeOutput` zip.

Patchers and their patches:
- **iboot.c `patchiBoot`**: image-type dispatch (`find_iboot_type`): LLB/iBSS → `PATCH_RSA` (`find_verify_shsh` → `mov r0,#0; str r0,[r8]`); iBoot → RSA + debug + `PATCH_BOOT_PARTITION` + `PATCH_BOOT_RAMDISK` + `PATCH_BOOTARGS` (+`PATCH_CALL_SETENV` if version > 2261); iBEC → RSA + `PATCH_DEBUG` + `PATCH_TICKET` (`find_ticket1/2` NOP-out) + BOOTARGS + `PATCH_RAMDISK_BOOT` (appends `RAMDISK_BOOT` arg) (+CALL_SETENV). Boot-args written over the "reliance" string with xrefs fixed. **Note: this is a different patch set from the already-ported `image::iboot32` (iBoot32Patcher)** — different finders/constants.
- **kernel.c `patchKernel`**: supports **only xnu 2107 (iOS 6.0/6.1), 2783 (8.0–8.2), 2784 (8.3–8.4.1), 3248 (9.0–9.3.x)** — consistent with the config gate. Mach-O/kext (AMFI, sandbox, LwVM via `__PRELINK_INFO`) offset finding, then: `patch_text` (vm_fault_enter, vm_map_enter, vm_map_protect, mac_mount, csops, tfp0/pid_check), `patch_amfi` (PE_i_can_has_debugger GOT, cs_enforcement GOT, execve hook payload), `patch_sandbox` (sb_evaluate hook using embedded `mac.h`/`sb_payload.h` payload, `patch_sbops` ret0), `patch_lwvm` (PE_i_can_has_kernel_configuration GOT, jump, mapForIO). Per-version finder variants (`_ios6`, `_84`, `_90` suffixes) from patchfinder.c.
- **asr.c `patchASR`**: find `image_failed_signature`/`image_passed_signature`, branch the former to the latter (`make_b_w`), then recompute SHA-1 code-directory slots (uses OpenSSL SHA1 in C).

**Never reachable from Legacy-iOS-Kit — skip:**
- `daibutsu.c` standalone binary (whole file; `DaibutsuBundles/`, `fstab_ro.h`, and **`haxx.h`/`dyld_shared_cache_haxx` — the 315 KB blob is only used there**, installed as ramdisk `/sbin/reboot`; the `-daibutsu` path in main.c replaces it with `reboot.sh` + bin.tar).
- main.c: `-s`/`-S` (custom root sizes), `Update Ramdisk`, APTicket without `-base`, `FirmwarePatches`/`RamdiskPatches`/`FilesystemPatches` bsdiff machinery (`doPatch`, `doPatchInPlace*`) — that's the classic `ipsw` binary's job.
- `pwnutil.c mergeIdentities`; patchfinder `find_release_env_set_whitelist`, `find_whitelist`, `find_go_cmd_handler` (`PATCH_GO_CMD_HANDLER` never set).
- `ticket.c`, `validate.c`, `nor_files.c` patch-application paths (bundle model replaces them), `img3.c` beyond what `image::img3` already does, `outputstate.c`/minizip (replaced by `firmware` zip), `plist.c` (replaced by `plist` crate).

- `resources/firmware/src/ios9.tar` (`FilesystemPackage` for 8/9 powder targets).

Source: powdersn0w_pub repo, record commit + sha256.
- Kernel patch payloads embedded in `xpwn/include/mac.h` (39 KB) and `sb_payload.h` (3.4 KB) — embed as Rust byte constants or assets with provenance.
- Tiny blobs `fstab.h` (rw fstab, 63 B) and `pref.h` (SBShowNonDefaultSystemApps bplist, 76 B) — embed as constants in the builder module (they are source constants, provenance = the C header).

**Not needed:** `haxx.h` (daibutsu standalone only), `fstab_ro.h`, powdersn0w_pub's shipped `FirmwareBundles/*/Info.plist` (Legacy-iOS-Kit generates bundles at runtime; our port builds them in memory), the 54 `Down_*` patch bundles (classic-ipsw path).

## 4. Module decomposition (one commit per slice, dependency-ordered)

1. **`crates/image`: LZSS (`complzss`) codec.** Confirmed gap — no LZSS/LZSSVN anywhere in the workspace; kernelcache IMG3 payloads are LZSS-compressed and xpwn's img3 AbstractFile layer decompresses/recompresses transparently. Add `image::lzss` + integrate with `img3` payload extract/replace round-trip. Test: known kernelcache decrypt→decompress→MH_MAGIC, recompress→byte-identical (or boot-valid) round trip.
2. **`crates/image::patchfinder` + `powder_iboot` + `powder_asr`.** Port patchfinder.c primitives actually used (see §2; ~50 finders), then iboot.c and asr.c patchers as new modules (do **not** shoehorn into `iboot32`, which ports iBoot32Patcher's different option set — keep both, share finders where identical). Fixture tests per device/build (opt-in, not CI-gated).
3. **`crates/image::kernel32`.** kernel.c port: Mach-O/prelink parsing helpers, offset finders, patch_text/amfi/sandbox/lwvm for xnu 2107/2783/2784/3248. Largest single slice; may be split per version family (6, then 8, then 9) if review size demands.
4. **`crates/firmware::powder_bundle`.** Typed model replacing `Info.plist` + `config.plist`: output of porting `ipsw_prepare_bundle`/`ipsw_prepare_config`/`ipsw_prepare_keys`/`ipsw_prepare_paths` logic (key lookup against existing `FirmwareKeySet`, `RootFilesystemSize` from ramdisk options plist, `RamdiskOptionsPath` rule, Firmware dict entries per version family, FirmwarePath/FirmwareReplace path lists, daibutsu keys). Plus generators for `systemversion.tar`, `iBoot.tar`, and the `reboot.sh`/partition-script templating.
5. **`crates/kit::powder`.** The builder = main.c port, structured as request → plan → build with an event stream per AGENTS.md: rootfs DMG decrypt/grow/untar/punchd/daibutsu-moves/fstab/pref/rebuild (reusing `image::hfs`, `dmg`, `firmware::custom` zip writer), ramdisk grow/ASR-patch/package/reboot-hook/exploit injection, NOR replacement + TYPE rewrites + APTicket scab reseal for `-base` flows, BuildManifest path rewrites. Sub-slices: 5a non-jailbreak single-IPSW (path A minimal), 5b jailbreak payload matrix + kernel patching, 5c `-base` two-bundle mode (paths B/C) incl. exploit/partition injection.
6. **`crates/assets`**: add the missing resources from §3 (can land ahead of 5b/5c).
7. **Restore-side wiring.** `crates/kit::multipart` already consumes an externally built part-2 IPSW for A4 3.x/4.0–4.2.x and reimplements `ipsw_prepare_multipatch` — wire slice 5 output in as that part 2. For A5/A6 powder and 4.3 single-IPSW powder, extend `workflows::restore` planning: ticket from **base-version** blobs (`TicketPolicy`), pwned boot chain from the custom IPSW's patched iBSS/iBEC, `--skip-first` equivalent for multipart, and the post-restore "ibob" nvram fixup (restore.sh:8269). Exact gap here is the least-mapped area (see §5) — scope it with a short explore pass over `restore_prepare`/`restore_device` in restore.sh before starting.
8. **`apps/cli`**: `lik` flags mirroring `--ipsw-verbose`, `--bootargs`, `--memory`, `--skip-first`, openssh/bbupdate toggles.

## 5. Risks / unknowns

- **patchfinder fragility**: 82 KB of hand-rolled ARM pattern matching; per-build sensitivity. Needs fixture tests with real decrypted kernelcaches/iBoots/iBSS per supported (device, build) — hardware/wiki-derived fixtures, opt-in.
- **LZSS details**: verify xpwn's img3.c behavior for iOS 9 kernelcaches (compression type byte handling, recompression fidelity) before committing the codec API.
- **`-ramdiskgrow 10` units**: main.c grows by `(totalBlocks + ramdiskGrow) * blockSize`, i.e. *blocks* despite the tiny value; confirm against xpwn semantics during port (possible upstream quirk to replicate, not fix).
- **"Buggy" upstream markers**: the APTicket/scab path is commented `// buggy`; multipart already reseals tickets successfully — reconcile the two implementations.
- **Root-size estimate**: main.c's "poor estimate" (+1 MB per tar MB) must be mirrored exactly or HFS growth will diverge.
- **iBSS/iBEC output re-encryption**: xpwn re-encrypts patched images with the same firmware IV/key (AbstractFile layering); mirror this in `image::img3` encrypt path.
- **9.3.5/9.3.6 and betas**: no untether tar for 9.3.5/6 in powder mode; iOS 8 betas 1–2 unsupported (kernel patcher); keep these gates in planning code.
- **Restore-consumption gap (needs verification)**: exact `restore_prepare` flow for powder restores (base-blob TSS, personalization, iBSS handoff, options overrides) was only sampled, not fully read — recommend an explore pass over `restore_prepare`/`restore_device` before slice 7.
- Not read in full: `patchfinder.c` bodies (header inventory only), `outputstate.c`/`minizip` (subsumed), `dmg`/`hfs` C internals (workspace equivalents already exist and are the reference).
